# 水位与水量定义

id、station为字符串。time含时区，统一UTC，日账在+08:00午夜拆分。level单位m；inflow/outflow单位m3/s或L/s，归一m³/s；空值不等于零。负流量与曲线外水位隔离。
curve为[[水位,库容],...]，水位及库容必须严格递增，库容非负，单位m与m³。只对范围内水位分段线性插值，端点允许。
同站同刻按version最高记录采信，同版不同值全部隔离。重复旧版有独立证据。输入=采信+隔离；原始行号保留。
相邻观测间以梯形积分计算流量体积，超过max_gap_hours则不插补。日界处先线性插出流量与水位，再分别积分及按曲线换算库容。日账是已覆盖时段的收支，覆盖不足24h始终待补测。
日收支差=库容变化-入库+出库，绝对值超过tolerance_m3需复核。缺测优先于超差。无蒸发降雨模型，差额不自动认作漏损。本次不纳入气象补水与外控调度：日账只有采信测次的入库、出库和库容变化三项。

日账并列两套日期口径，同一行不混用：
- 凭证日（voucher_date）：测站按本地日签发回执的口径。日期取观测时刻的+08本地日，入库与出库总量等于改拆口径前的原值；传播时延不改变已签发回执的日期和总量。
- 到达日（arrival_date）：库区日账口径。入库与出库按观测时刻加传播时延后的+08本地日归集，跨午夜来水按实际到达日落日，不再跟随测站日期。`travel_hours`为传播时延，单位为h，可为标量（全站）或`{测站: 小时}`，取0–168，缺省0。

库容变化量测自观测水位，不属于传播中的水量，留在观测（凭证）日；到达日只重排入库与出库。因此每个到达日的收支差仍为“当日库变-当日到达入库+当日到达出库”，可直接人工归因。传播时延只在两套口径内重新分配水量，不复制、不丢失：凭证日总量与到达日总量都等于流量积分总量，M7对两套口径分别核对。

发布到达日库区日账（`POST /api/ledger/publish`）以`(station, arrival_date)`为业务键。发布前整批校验，任一日缺测站或日期、数值非有限、入库出库为负、状态未知或同站同日重复时整批拒绝，旧版日账保持原样，不写半条。
发布以每个测站已确认（状态“完整”且已入账）的最大到达日为续跑水位线：水位线及之前的到达日保留旧版值、不重复入账，也不能用重算值改写其日期和水量；水位线之后从已确认到达日续跑。状态为“缺测”的到达日首次发布保留为未确认，可在水位线推进前反复重跑补齐，补齐为“完整”后转为已确认并推进水位线。因此重跑同一天只保留一行，续跑不会重复入账，也不会回填被后续已确认日覆盖的历史日期。
数值为Decimal字符串，日切与整段积分容许1e-9m³以内十进制除法尾数。规则参数和输入摘要参与幂等ID；批次原子保存，复核版本冲突返回409。

原始到达序小于此前最大事件时刻的测次标记arrival=迟到，仍保留并按事件时间排序积分，迟到不会推进水位回退。
